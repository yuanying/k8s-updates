[Kubernetes 1.37 の CHANGELOG](https://github.com/kubernetes/kubernetes/blob/master/CHANGELOG/CHANGELOG-1.37.md) から SIG Cluster Lifecycle の取り組みについてまとめました。

## :warning: アップグレード時の注意事項

- `Urgent Upgrade Notes` に SIG Cluster Lifecycle の項目はなし。ただし、`kubeadm` の `v1beta3` API が削除されているので、まだ `v1beta3` の設定ファイルを使っている場合は注意が必要です（詳しくは「その他」を参照）。

## :dizzy: 項目ごとの変更

### :arrow_left: 依存

- デフォルトの `etcd` バージョンを `v3.7.0-rc.0` に更新しました。([#139427](https://github.com/kubernetes/kubernetes/pull/139427), [@Jefftree](https://github.com/Jefftree))

- デフォルトの `etcd` バージョンを `v3.7.0` に更新しました。([#140333](https://github.com/kubernetes/kubernetes/pull/140333), [@Jefftree](https://github.com/Jefftree))

:::note info
`etcd` が `v3.7` 系になりました。rc を経由して、最終的に `v3.7.0` が採用されています。
:::

- Kubernetes が利用する `etcd` クライアントライブラリを `v3.6.10` に更新しました。([#138393](https://github.com/kubernetes/kubernetes/pull/138393), [@humblec](https://github.com/humblec))

### :do_not_litter: 非推奨

- `KubeProxyConfiguration` が指定されていない場合、もしくは `mode` フィールドが空の場合、`kubeadm` は `KubeProxyConfiguration.mode` に明示的に `iptables` を設定するようになりました。`v1.37` の `kube-proxy` は、将来のリリースでデフォルトモードを `nftables` に移行する計画の一環として、このフィールドが明示的に設定されていない場合に警告を出力します。([#139777](https://github.com/kubernetes/kubernetes/pull/139777), [@neolit123](https://github.com/neolit123))

- `kubeadm`: `kube-proxy` の `ipvs` モードが `v1.35` から非推奨になっていることについて、（遅延した）警告を追加しました。新しい Linux カーネルを使っているユーザーは、`v1.33` で GA になった `nftables` モードを使用すべきです。古いカーネルの場合は、引き続きデフォルトである `iptables` を使用できます。([#139067](https://github.com/kubernetes/kubernetes/pull/139067), [@neolit123](https://github.com/neolit123))

:::note info
`kube-proxy` のデフォルトを `nftables` にする準備が着々と進んでいる感じ。`kubeadm` が `iptables` を明示的に設定するようになったので、デフォルトが変わったタイミングで既存クラスタのモードがいきなり変わる、ということは避けられそうです。
:::

### :construction_site: APIの変更

- `kube-apiserver` の CBOR エンコーダーが、コレクションを一括ではなくアイテムごとにエンコードするように変更されました。([#138808](https://github.com/kubernetes/kubernetes/pull/138808), [@chenk008](https://github.com/chenk008))

- API の Go 型でインライン化された `TypeMeta` フィールドの json タグを、`",inline"` から `""` に変更しました。`inline` は json シリアライザーが認識するオプションではなく、marshal / unmarshal の挙動にも影響していませんでした。([#138260](https://github.com/kubernetes/kubernetes/pull/138260), [@liggitt](https://github.com/liggitt))

:::note info
`encoding/json` に `inline` オプションはなく、意味のないタグだったようです。挙動は変わらないので見た目の修正。
:::

### :unicorn: 機能

- `EtcdRangeStream` beta フィーチャーゲートが追加されました。watch cache の初期化時に、ページングされた `Range` リクエストではなく、単一の `RangeStream` RPC で `etcd` からオブジェクトをストリーミングします。([#136915](https://github.com/kubernetes/kubernetes/pull/136915), [@Jefftree](https://github.com/Jefftree))

:::note info
`etcd` `v3.7` の新機能を使っているっぽい。大きなクラスタでの `kube-apiserver` 起動時の負荷が下がりそう。
:::

- CEL admission policy の評価で、オブジェクトの走査に遅延評価かつアロケーションなしのリフレクションベースのユーティリティを採用し、リクエスト処理中の CPU 使用量と GC のオーバーヘッドを大幅に削減しました。([#138771](https://github.com/kubernetes/kubernetes/pull/138771), [@lalitc375](https://github.com/lalitc375))

- CoreDNS を `v1.14.3` に更新しました。([#138536](https://github.com/kubernetes/kubernetes/pull/138536), [@yashsingh74](https://github.com/yashsingh74))

- CoreDNS を `v1.14.4` に更新しました。([#139735](https://github.com/kubernetes/kubernetes/pull/139735), [@yashsingh74](https://github.com/yashsingh74))

- CoreDNS を `v1.14.6` に更新しました。([#140497](https://github.com/kubernetes/kubernetes/pull/140497), [@yashsingh74](https://github.com/yashsingh74))

:::note info
1リリースで CoreDNS が3回も上がってる。最終的には `v1.14.6`。
CoreDNS 自体は月1くらいでリリースされているので、3回上がっていてもおかしくはないのですが、いつもは1リリースで1回くらいしか上がっていないので、なんでだろう？と思ってちょっと調べてみました。が、特に理由はなかったです。
調べている途中で、`kubeadm upgrade` 時に Corefile を移行するための [coredns/corefile-migration](https://github.com/coredns/corefile-migration) の存在を知りました。CoreDNS を上げるたびに、こちらにも新しいバージョンを追加する必要があるようです。
:::

- `kubeadm`: `kubeadm init` と `kubeadm upgrade` の実行時に `kube-proxy` の `DaemonSet` にパッチを当てられるよう、`kubeproxydaemonset` パッチターゲットを追加しました。既存の `corednsdeployment` パッチターゲットと同じ使い方ができます。([#138090](https://github.com/kubernetes/kubernetes/pull/138090), [@SataQiu](https://github.com/SataQiu))

- `kubeadm`: `kube-apiserver`、`kube-scheduler`、`kube-controller-manager`、`etcd` の `preflight check` である `Port-xx` が、kubeadm の設定で各コンポーネントに指定されたアドレス（`localAPIEndpoint.address` フィールド、もしくは extraArgs の `--bind-address`）に bind してチェックするようになりました。以前はアドレスを指定せずに `net.Listen()` を呼んでいたため、そのポートで利用可能なすべてのユニキャスト / エニーキャスト IP アドレスに bind していました。([#138250](https://github.com/kubernetes/kubernetes/pull/138250), [@lentzi90](https://github.com/lentzi90))

:::note info
特定のアドレスにだけ bind する構成の場合、関係ない他のアドレスでポートが使われているだけで `preflight check` が失敗していたのが直る。
:::

- `kubeadm`: `NodeLocalCRISocket` フィーチャーゲートを削除しました。この機能は以前のリリースで GA に昇格し、有効状態に固定されていました。([#138645](https://github.com/kubernetes/kubernetes/pull/138645), [@neolit123](https://github.com/neolit123))

- `kubeadm`: `preflight check` の `ContainerRuntimeVersion` は、インストールされているコンテナランタイムが `RuntimeConfig gRPC` メソッドをサポートしているかを検証します。`v1.38` より古い `kubelet` バージョンでは、`preflight warning` を返します。([#139122](https://github.com/kubernetes/kubernetes/pull/139122), [@carlory](https://github.com/carlory))

:::note info
1.36 のときは「`v1.37` より古い `kubelet` では warning」だったのが、`v1.38` に先送りされました。`RuntimeConfig gRPC` メソッドのサポートが必須になるのは `v1.38` からになりそう。
:::

### :bug: バグ、もしくはリグレッション

- `Server-Side Apply` で、コンテナ型（list や map）へのパッチ適用時に、以前は成功していた apply リクエストが `422 required` エラーを返すことがあったリグレッションを修正しました。([#140294](https://github.com/kubernetes/kubernetes/pull/140294), [@jpbetz](https://github.com/jpbetz))

- `kubeadm join` で、クラスタから `kubeadm-config` ConfigMap を取得する際に、オプションのコンポーネント設定向けに使われていた 350ms の短いリトライではなく、`KubernetesAPICall` タイムアウト（デフォルト 1 分）を使うようにして信頼性を向上させました。`kubeadm reset` のような呼び出し元が引き続き短いリトライを使えるよう、`FetchInitConfigurationFromCluster` に `shortConfigMapGet` パラメータが追加されています。([#139667](https://github.com/kubernetes/kubernetes/pull/139667), [@damdo](https://github.com/damdo))

:::note info
350ms はさすがに短い…。
:::

- `KubeProxyConfiguration` でデフォルト以外の `bindAddress` を設定した場合の、`kubeadm` の警告ロジックを改善しました。([#139989](https://github.com/kubernetes/kubernetes/pull/139989), [@vinayakray19](https://github.com/vinayakray19))

- `kubeadm` の `etcd` learner の昇格処理で、昇格自体は成功しているのにクライアント側で一時的なエラーが返ってきたケースを正しく扱うようにし、不要な `etcd` join の失敗を防ぐようにしました。([#139842](https://github.com/kubernetes/kubernetes/pull/139842), [@jihyun-huh](https://github.com/jihyun-huh))

- `kubeadm`: `kubeadm init` で、デフォルトの `admin.conf` と `super-admin.conf` のパスが使われている場合、ファイルは読み込むものの、メモリ上の kubeconfig は `ClusterConfiguration.controlPlaneEndpoint` ではなく `InitConfiguration.localAPIEndpoint` を指すように構築するよう変更しました。これにより、最初の `kube-apiserver` が起動した後にプロビジョニングされるような、遅れて用意されるロードバランサーでの問題が解消されました。([#138449](https://github.com/kubernetes/kubernetes/pull/138449), [@neolit123](https://github.com/neolit123))

:::note info
Cluster API などで、LB が `kube-apiserver` の起動後に作られる環境では、`kubeadm init` が LB 経由で API Server にアクセスしようとして待たされる、という問題があったっぽい。
:::

- `kubeadm`: `kubeadm join` で、TLS bootstrap 用 kubeconfig の current-context が contexts リストに存在しない場合、nil pointer dereference で panic するのではなく、わかりやすいエラーメッセージを返すように変更しました。([#138853](https://github.com/kubernetes/kubernetes/pull/138853), [@alexmchughdev](https://github.com/alexmchughdev))

- `kubeadm`: HTTPS 経由の cluster-info discovery で HTTP レスポンスのステータスコードをチェックするよう変更しました。200 以外のレスポンスの場合、わかりにくい kubeconfig のパースエラーではなく、明確なエラーが出るようになります。([#138852](https://github.com/kubernetes/kubernetes/pull/138852), [@alexmchughdev](https://github.com/alexmchughdev))

- `kubeadm`: `etcd` クラスタのステータスチェックを、全メンバーの健全性を見るのではなく、クォーラムベースで判定するよう変更しました。十分な数の健全な voting member がいれば、チェックは失敗しなくなります。([#138403](https://github.com/kubernetes/kubernetes/pull/138403), [@ahrtr](https://github.com/ahrtr))

:::note info
メンバーが1台落ちているだけでチェックが失敗していたのが、クォーラムを満たしていれば OK になった。`etcd` のメンテナである ahrtr さんによる修正。
:::

- `kubeadm`: `MemberPromote` で、対象のメンバーがすでに voting member である場合は `etcd` の promote API 呼び出しをスキップするよう修正し、不要なリトライとタイムアウトを回避しました。([#138390](https://github.com/kubernetes/kubernetes/pull/138390), [@wgkingk](https://github.com/wgkingk))

:::note info
1.36 に引き続き、今回も `etcd` の learner 周りの修正が多い。
:::

- `kubeadm`: PKI の鍵読み込み時に、秘密鍵と公開鍵の種類が一致しない場合に `kubeadm` が panic する問題を修正しました。([#138939](https://github.com/kubernetes/kubernetes/pull/138939), [@SataQiu](https://github.com/SataQiu))

- `kubeadm`: `kubeadm init phase certs --dry-run` で、既存の CA ファイルが正しくコピーされるよう修正しました。([#139339](https://github.com/kubernetes/kubernetes/pull/139339), [@ErikJiang](https://github.com/ErikJiang))

- `kubeadm`: worker node の `kubeadm join` では、`LocalAPIEndpoint` のデフォルト値設定をスキップするようにしました。([#138692](https://github.com/kubernetes/kubernetes/pull/138692), [@clwluvw](https://github.com/clwluvw))

- `kubeadm`: `kube-apiserver` の `kubelet` クライアント用に、専用の ClusterRole `system:kubelet-api-admin` を使うようにしました。([#138957](https://github.com/kubernetes/kubernetes/pull/138957), [@neolit123](https://github.com/neolit123))

- `kubeadm`: `init` 時に、ノード固有の `systemd-resolved` の `resolvConf` パスを、クラスタ全体で共有される `kubelet-config` ConfigMap に保存しないようにしました。([#141627](https://github.com/kubernetes/kubernetes/pull/141627), [@HirazawaUi](https://github.com/HirazawaUi))

:::note info
こちらは `v1.37.1` での修正。`init` したノードの `resolvConf` のパスが他のノードにも配られてしまい、`systemd-resolved` を使っていないノードで困ることがあったようです。
:::

### :goat: その他（クリーンアップまたはFlake）

- `kubeadm`: `v1.31` から非推奨になっていた `v1beta3` API を削除しました。`v1.35` の `kubeadm` バイナリで `kubeadm config migrate` コマンドを使うことで、`v1beta4` へ移行できます。また、`v1beta3` との後方互換性のためだけに残されていた kubeadm 固有のフィーチャーゲート `PublicKeysECDSA` も削除しました。ECDSA 鍵のサポートは、`v1beta4` の `ClusterConfiguration.EncryptionAlgorithm` フィールドとして追加されています。加えて、`v1beta4` のコピーである `v1` API をプレースホルダーとして追加しましたが、これは実験的なもので、まだ使用できません。([#136016](https://github.com/kubernetes/kubernetes/pull/136016), [@neolit123](https://github.com/neolit123))

:::note info
ついに `v1beta3` が削除されました。そして `v1` API の姿が見えてきた！まだ使えないけど。
:::

- `kubeadm`: サポート対象のコントロールプレーンバージョン `v1.34`、`v1.35`、`v1.36` 向けの `etcd` バージョンを `v3.6.10` に更新しました。([#138392](https://github.com/kubernetes/kubernetes/pull/138392), [@humblec](https://github.com/humblec))

- `kubeadm`: サポート対象のコントロールプレーンバージョン `v1.34`、`v1.35`、`v1.36` 向けの `etcd` バージョンを `v3.6.11` に更新しました。([#138746](https://github.com/kubernetes/kubernetes/pull/138746), [@humblec](https://github.com/humblec))
